# 基础版架构

## 数据与权威

后端SQLite是账号、座位、会话、比赛和累计战绩权威。每场比赛分配独立端口，生成独立服务间密钥，托管模式启动一个独立Unity进程。
Unity服务器在连接批准阶段向后端核销一次性票据。由返回的用户/队伍/座位绑定到原有NetworkObject，不读取客户端自报的队伍。
客户端只在拥有的NetPlayer上调用输入ServerRpc，服务器验证有限向量和递增序号，丢弃旧输入；超过0.3秒无新输入即清空操作。
角色Rigidbody2D仅在服务器模拟。NetworkVariable同步位置、朝向、生命、武器、道具、统计；客户端指数插值。
尸体复用原NetworkObject与刚体，保持队伍座位和绳链。死亡清空武器、道具、盾和冲刺；团队绳索状态继续按原截止时间存在。

## 网络频率

服务器物理30Hz，NetworkVariables随NGO30Hz tick发送变化。拾取物、弹丸、炸弹、绳索路径用15Hz可靠ClientRpc快照同步，支持NGO可靠分片，不依赖单UDP包大小。
这是一版可用的低人数原型；没有客户端移动预测、网络补偿、增量弹丸压缩。高延迟优化与流量测量列为后续工作。
业务侧WebSocket即时通知，HTTP房间轮询1秒兜底。认证刷新重试只有一次；敏感凭证不进入日志。

## 绳索

RopePath将地图矩形掩体外扩后建立可见性图，端点加入图后求最短无遮挡折线路径。
RopeLink按折线总长度计算伸长，力方向朝端点的相邻折点；弹性、阻尼、最大力影响两端刚体。
过度伸长时削减分离方向速度，不使用位置瞬移。可见路径由服务器下发，客户端不另算约束。
支持同队按seat排序的相邻链段，2/3/4人同一套逻辑。尸体质量提高但仍被拉动。
限制：目前只支持轴对齐矩形掩体；路径取最短解，没有持续维护缠绕拓扑，绕柱两侧等长时可能切换折线。力学是弹性软约束，冲刺时可短暂超过ropeLength。稳定手感与多机压力测试仍需执行。

## 伤害与胜负

武器首次拾取将当前/最大血量设为配置值，持有期间拒绝替换；死亡后空手。
射击用服务器推进弹丸，每步RaycastAll按距离处理先墙后角色，避免高速穿透。近战验证朝向、距离和遮挡。炸弹3秒延迟范围敌伤并检查掩体遮挡。
盾优先扣减，伤害统计记录实际消耗的血与盾。死亡只在Alive从true进入零血时计一次，致命伤来源计击杀。
每物理帧处理完所有伤害再检查全灭，双方同时全灭按平局处理。超时比较存活人数，再比血量，不含盾。
结算名单与服务器固定roster核对，事务写比赛和累计统计；重复结算只返回duplicate。异常中止不计分。

## 断线

游戏断线保留实体20秒，清空控制与旧序号；重新申请票据后ChangeOwnership回原实体。仍在线的同账号不能被第二客户端接管。
超时变为尸体。离线尸体不自动复活，恢复连接后可正常在区域内救援，避免离线反复复活/死亡刷统计。
等待房间失联约20秒后释放成员，房主自动交接。
服务器5秒心跳，20秒失联或启动90秒超时即Aborted；后端重启同样中止旧局。

## 内容与工程

Resources/GameConfig.json统一玩法参数和地图。地图纯数据生成几何、碰撞和绳索图。UI读取开放地图列表。
Assets/BoundShoot/Resources保存两种实际NetworkObject prefab；Editor BuildTools可生成并保存启动场景。
运行时Bootstrap区分普通客户端和 -matchFile 服务器；Windows同一可执行文件用于本机独立服务器验证，Linux使用Dedicated Server构建目标。
