# 行走动画卡顿修复

2026-10-29。仅修改本地 Unity 工程、Sprite 元数据和说明；不生成构建、不更新云端。

## 原因

原先 `CyberPlayerView` 每个渲染帧直接比较 Transform 位移，以单帧是否移动决定播放行走或待机。物理更新是30Hz，显示通常为60Hz或更高，在两个物理步之间没有新位置时就会切到待机，下一次物理步又切回行走。此外房主 Rigidbody 没有插值，角色位置直接按物理步跳动。

动作图按完整网格切片，但生成图中的每帧不完全居中。使用画布中心作为所有帧的锚点，会让角色在切帧时左右或上下跳动，六帧循环交界处尤其明显。

## 修改

- `VegetableWalkCycle` 连续维护六帧、12fps的行走周期。位置样本间允许100ms停止缓冲，避免渲染帧间隙触发待机；真正停止后回待机。出生/传送的大位移重置周期，不当作行走。
- 房主显示启用 `RigidbodyInterpolation2D.Interpolate`，客户端保留原网络插值；没有增加物理或网络发送频率，也没有改变服务器碰撞/绳索求解方式。
- `NetPlayer` 在 `LateUpdate` 播放角色动画，读取当帧已经处理的显示位置。
- 八角色前24帧（行走和待机）的 Sprite 使用一致画布尺寸，根据不透明内容注册水平中心和脚底锚点。角色显示统一脚底位置；倒地、受伤、复活等特殊姿势仍使用原画布锚点。没有修改原始PNG。
- 导入器保存该注册规则，重新执行 **Bound Shoot → Art → Prepare Vegetable Demo** 后也不会退回旧锚点。已重新导入现有资源，正常Play不需要手动导入。

## 验证

编辑器测试报告：`logs/walk-fix-edit.xml`，43项通过。新增检查覆盖30Hz位置样本与60/120/144Hz渲染混合时不闪待机、停止和传送行为、不同帧率的播放节奏，以及八角色全部192张站立帧的画布和锚点。

运行测试报告：`logs/walk-fix-play.xml`，4项全部通过。覆盖训练房插值设置与生命周期、四人和八人网络对局/重开、AI完整对局。四/八网络参与者仍为同一Unity测试进程的独立NetworkManager和真实本机UDP连接。

在 Unity 中停止原 Play 后重新进入训练房或本地对战，持续走动并停止，检查正面、侧面、背面及行走循环交界。原图各姿势的造型差异仍然保留，自动化检查不代替真人对动画观感的判断。
