# 产品提升首批实施：M0 / M1

2026-10-30。对应v2策划BS-01至BS-05。交付本地Unity源码和显示资源配置，不构建、不部署、不推送。没有覆盖GameConfig中的枪械数值、道具倍率或同伴地图。

## 已接入的变化

### 等待和协作规则

手动本地房间不再触发专用服的60秒连接准备超时。等待后开战和重开后等待使用同一规则；专用服自动等待依然有超时中止。新增2v2/4v4两模式首次与重开后各90秒游戏时间等待回归，用加速时间执行，不冒充现实时间长挂机测试。

`DESIGNER_HANDOFF.md`已改为现行规则：踩不同枪直接换、同枪不消费、不回血、不刷冷却；默认2v2最大4v4；训练队友无自主AI；地图明确使用typed pickups/revivalZones；本地改动不用逐次更新云端。地图选择/直接测试尚未实现，不把旧线上按钮当作本地功能。

### 连续弹丸

每次权威开火产生世界内递增shotId，弹丸保留固定身份、出生时间、武器和方向。开火事件立即建立显示，快照校正同一ID；不再以列表下标对应弹丸。客户端在显示帧之间连续推进，并限制外推最多150ms或剩余射程，防止断包后无限飞行。

权威命中或到期事件回收显示；快照缺失也回收。近期回收ID和每发射者已处理序号防止旧事件重复显示。重开增加RoundId，旧轮消息不能污染新轮；结算清掉所有显示弹丸。头部/曳光对象复用池，视觉外推先检测障碍，不能把子弹画到墙的另一侧。

服务器仍使用原来的物理步进、射线扫掠和伤害计算；客户端不因看到弹丸触碰就扣血。没有为了掩盖显示跳动而提高物理或网络频率。完整移动预测/回滚、弱网调参和二进制增量协议仍是后续任务。

### 发射者归属与枪口

开火事件携带准确的NetworkObjectId、shotId和发射时武器，直接在对应NetworkManager内找发射者；移除“查附近第一个同队玩家”的猜测。按发射序号去重，不因后来换枪而使用错误音色。

四武器共用 `Resources/WeaponPresentation.json` 描述显示尺寸、握把、枪口、后坐量、枪口火光和曳光长度。实际持枪姿势、逻辑枪口和开火火光从同一配置推导，左右镜像时握把不漂移；持枪高度根据枪管挂点补偿，保证各角度枪口与鼠标瞄准线共线，防止左右射击发生不同的横向偏移。短暂固定开火朝向，避免远端插值中的旧朝向和新火光不一致。匕首使用近战斩弧和短音，不再冒充枪口火光或播放爆炸音。

枪口放大后有两种特殊处理：角色到枪口跨墙时不开出穿墙弹；敌人在角色与枪口之间时先结算近距离命中，不能把敌人跳过去。四种武器的伤害/冷却/弹速/最大生命数值没有变化，但弹丸发射起点现在更贴近实际枪口，最终对战距离仍需设计同学观察。

### 绳索显示

物理路径仍由原连续绕障碍求解器维护，显示路径不写回物理路径。房主和远端在LateUpdate将绳端对齐当帧显示位置，解决Host插值人物和固定物理步绳端的错拍。

增加随长度比例变化的粗细/亮度、接近绷紧时的朝拉力方向箭头、绕障碍拐点小标记。远端绳索端点也使用稳定网络对象ID，避免在多会话测试里按队伍/座位找错对象。暂无新的Buff HUD、收缩/延长专属图标；这属于BS-06。
