# 输入名字即可开始的2v2调试版

2026-10-28。美术暂停，讨论完整保存在 ART_STYLE_OPTIONS.md。本次不替换美术，不改关卡布局或枪械数值。

## 玩家操作

1. 打开 builds/Windows/BoundShoot.exe。
2. 输入名字，例如 yafo777，点击“进入房间”（也可按回车）。没有注册、密码或建房号。
3. 自动坐进唯一的2v2房间。一个人时，其他三席是AI；其他真人进入时替换AI。
4. 点击“开始游戏”，自动连接云端对战。一局结束后显示结算，返回房间可再次开始。

所有真人都可以开始，不用单独准备。可点击AI座位换位；被真人占用的座位不可抢占。当前只有四个真人容量，对局中不插入新的玩家，开局后新名字需要等该局结束。退出按钮释放座位；直接关闭窗口后，等待房间会在离线检测后释放座位。名字在线时同名登录会提示更换，离线约20秒后可以重入。同一名字对应同一个调试ID和战绩，不需要密码。

## AI做什么

机器人在独立Unity服务器上执行，不启动额外exe客户端。不修改真人输入、不直接扣血，也不凭空装备武器。它会去补给点拾枪、绕过矩形障碍、追踪敌人、按当前武器射程移动与射击。与真人同队时尽量留在绳长范围内，队友倒地时尝试牵引到复活区；拾到携带道具时按距离条件使用。机器人使用正常的刚体、绳索、武器冷却、子弹、伤害和结算逻辑。

这是用于验证玩法的基础AI，不是经过平衡与战术训练的对手；复杂绳索绕角、救援和道具决策仍需实战调整。没有改动设计同学负责的数值或地图。

## 云端更新：这次后端也必须更新

将本机 `builds/UploadToServer/` **里面的四个文件夹** 合并复制到 `/home/ubuntu/Bound_Shoot/`：

| 本机文件夹 | 云端目录 |
|---|---|
| backend | /home/ubuntu/Bound_Shoot/backend/ |
| server | /home/ubuntu/Bound_Shoot/server/ |
| content | /home/ubuntu/Bound_Shoot/content/ |
| deployment | /home/ubuntu/Bound_Shoot/deployment/ |

同名源码和程序覆盖，保留云端 backend/.env、state 数据库、runtime。不上传QA、logs或本机测试数据库。然后执行：

~~~bash
cd /home/ubuntu/Bound_Shoot
bash deployment/activate-game-server.sh
~~~

脚本会安装后端依赖、编译更新后的TypeScript并重启项目服务；服务启动时自动迁移数据库。成功的health应出现 `"version":"0.2.0","entry":"name-only","mode":"2v2"`。首次curl连接失败后重试成功可能只是重启期间尚未监听。

不能只更新exe，旧后端没有名字入口，旧Unity服务器也不会运行这些AI。三端要使用本次同一版本。玩家仍直接访问134.175.153.218，TCP3000和UDP7777–7778不变，无需Bitvise转发。
