# AI 美术范围与第一批样张

日期：2026-10-28。此轮恢复风格讨论，仅制作两张提案板；尚未定稿，未导入 Unity。

## 美术清单

| 类别 | 本项目需要的内容 |
|---|---|
| UI | 名字入口、模式按钮、房间座位、HUD、生命/盾、武器/道具图标、结算；必要状态用图形和短标签表达 |
| 场景 | 地面、道路、背景装饰、树、石头、墙体、复活区；地面与可碰撞障碍分层 |
| 角色 | 基础角色、队色与外观区别、待机、走路、受伤、倒地、复活；枪械独立于身体 |
| 枪械/道具 | 狙击枪、手枪、AK、匕首；七种道具和问号盒；持有图、地面拾取图与 HUD 图标 |
| 反馈特效 | 枪口、弹道、命中、爆炸、冲刺、治疗、护盾；绳索拉紧、缩短/延长和弹性强化 |

音效和音乐另列音频工作，不计入这批图片素材。

## 用 AI 的制作流程

1. 从两版提案中确定一种风格，先锁定视角、轮廓、描边、颜色与阴影。角色优先原创小队员，不复制参考游戏角色。
2. 先完成一个角色、一把枪、一块地面、一个障碍的可运行样板，再扩展。先验收战斗中的可读性。
3. 按独立部件生成透明 PNG：角色、枪、道具、障碍分别输出。地图背景不能把所有障碍烘成一张图，否则不能直接用于关卡编辑器摆放。
4. 统一素材尺寸、脚底枢轴、枪口位置、默认朝右与排序规则。动画所有帧保持头盔、服装、体型和脚底基线；需检查循环中的漂移和缺帧。
5. 首版可用少量身体帧配合程序摆动、后坐、闪白与粒子。AI 连续帧必须切图、播放检查后才算可用，不把一张素材板当作已完成动画。
6. 每批记录生成来源、提示词、用途及验收状态；数值、碰撞和关卡数据仍由设计同学维护，程序将美术挂到已有对象上。

本项目建议优先清爽卡通：独立枪械旋转、曲线绳索和不同分辨率更容易统一。像素方案需要额外控制像素密度、整数缩放与旋转锯齿；此为项目实现判断。

## 本轮提案与来源

- [1 清爽卡通](../art-proposals/2026-10-28/style-1-cartoon.png)
- [3 像素街机](../art-proposals/2026-10-28/style-3-pixel.png)

两张均由内置 image_gen 从文字新生成，无参考图片输入；生成日期 2026-10-28。每张为 1536×1024、不透明的风格预览板，包含相同主题的场地、树石、独立枪和四个角色动作外观。保存于工程外的 art-proposals，不进入 Assets。

共同提示要求：原创俯视绳索射击场，低对比灰绿草地、暖沙路、四块大石与边缘树木；底部两石两树、一把朝右玩具步枪、同一藏蓝头盔/琥珀护目镜/青蓝背心角色的四个朝右走路姿势，稳定身份和脚底基线。卡通版要求平涂深色描边、圆润形状与少量阴影；像素版要求粗像素、有限色阶、清晰轮廓与无平滑边缘。

检查结论：两版风格可以比较，但四个角色姿势变化不足，卡通版腿部几乎重复；像素板也尚未验证严格逻辑像素网格。因此全部标记为“概念预览”，并非已切好的精灵表或可直接播放的走路动画。正式动画需单独生成并逐帧调整，本轮不接入游戏。
