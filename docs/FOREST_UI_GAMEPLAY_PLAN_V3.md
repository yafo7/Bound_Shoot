# Bound Shoot v3：森林高台、完整界面与强拖拽优化策划

2026-10-30 · 设计评审稿。源码基线：84b1c45。依据用户本次五组需求重新定义体验，配套来源记录见[素材与参考清单](FOREST_V3_SOURCES.md)。

本稿保留为本次实施依据。用户授权开始后已接入本地源码和素材，实际完成范围、测试与限制见[实施说明](FOREST_V3_IMPLEMENTATION.md)。没有构建、部署或推送Git。正文写设计目标，技术与素材条款集中在后部。

## 1. 这一版的完整体验

**进入游戏 → 输入名字并选蔬果 → 选择训练／本地AI／联机 → 房间入座与人数设置 → 森林中央高台对战 → 结算与再来。**

八个蔬果继续使用原身份，大枪仍突出。默认2v2，房内可以选择3v3和4v4。对战中右上角用红心显示自己的生命；角色始终位于画面中央。两侧低地出生，沿台阶进入中央高台交火；绳子能明显牵引队友。队友倒地不再去复活点，只要本队尚有人存活，5秒后原地复活。

### 1.1 本次明确更新的规则

| 用户要求 | v3设计结论 | 对旧版本的替代 |
|---|---|---|
| 输入ID时同时选角色 | 同一身份页面完成名字和八角色选择 | 取代输入名字后再去主菜单选角 |
| 三种房间 | 三张居中入口卡：训练房、本地AI对战、联机对战 | 将原创建/地址输入等调试操作放进对应联机流程 |
| 房内2/3/4队伍人数 | 房主在等待房切2v2、3v3、4v4；座位与链路立即预览 | 加入6人流程，不再只有2/4队伍大小 |
| 红心血量 | 右上红心填充/灰心缺失；护盾独立盾图标 | 取代主要靠文字读生命 |
| 角色严格居中 | 相机跟随本地角色的固定主体锚点 | 移除鼠标前瞻、滞后跟随、边缘钳制和使角色偏心的镜头震动 |
| 森林两层地形 | 两侧低地、中央高台，台阶是可通行连接 | 地图不再是大块草土贴图加散点障碍 |
| 自动复活 | 个人倒地5秒，到期仍有活队友则在倒地身体当前位置复活 | 删除复活区、区域停留进度和AI拖尸找复活点 |
| 更强拖拽 | 增加绳索牵引，并降低静止角色抵抗被拖动的制动力 | 不能只把弹簧系数乘大后仍由移动控制把人刹住 |

保留：原消灭/180秒计时竞技、无默认友伤、八外观无属性差别、踩枪立即自动切换、换枪不回血/不刷冷却、状态道具即用、冲刺/炸弹单槽E使用并覆盖、相邻座位绳链。地图中的高台不会附加占点获胜、额外伤害加成或新战利品机制。

## 3. UI全流程与页面设计

### 3.1 标题页

画面中心上方是「派对射击」，下方小字「Bound Shoot」；中央下方一个主按钮「进入游戏」，底部角落放设置和退出。森林庭院背景用轻微树叶/光斑运动，几名蔬果持枪作点缀；标题和按钮周围保持留白。

点击进入有0.15–0.25秒淡入或卡片滑动，直接到身份页。标题页负责建立作品感，不承载IP地址、版本号、服务器说明或规则长文。

### 3.2 身份页：名字与角色同时选

居中双栏：左边较大的角色待机/持枪预览＋名字输入框；右边4×2八角色卡。底部「确认进入」，左下返回。名字输入和角色选择同屏可操作，确认时同时保存。

点角色卡即选中，采用亮边、脚底选中标记和小勾，不只改变颜色。允许重复角色，名字按现有1–24字中文/英文/数字/下划线约束。校验错误贴在输入框附近，不用全屏警告。已用过的名字和角色可预填，但仍保留明确确认入口。

### 3.3 模式页：三个清楚的去处

| 入口卡 | 主图形 | 进入后的等待房 | 开始条件 |
|---|---|---|---|
| 训练房 | 靶子＋蔬果 | 本人、静止同队伙伴、对面靶子 | 本人即可开始；增加的伙伴没有自主AI |
| 本地AI对战 | 人物＋小机器人 | 本人自动入座，其余位置默认AI | 本人即可点击开始，不要求真人凑满 |
| 联机对战 | 两队人物＋连接图形 | 真人自动分配空位，房主可换位/调人数 | 默认等待真人满员；房主也可明确补AI，界面始终区分真人和AI |

三卡横向居中排列，底部显示本人头像和名字，点击可回身份页修改。卡片只需标题和小图标，必要时一行“练习／单人开战／与朋友一起”。

联机主路径是进入当前可用房间；房间不止一个时再给简洁列表。局域网创建/地址加入放入该入口的次级面板。正式公网版本不要求玩家输入IP或使用SSH。当前源码云端按钮尚禁用，实施时需要统一新版联机协议后再启用，不能只改按钮文字。

### 3.4 等待房：座位就是绳索关系

页面上方居中：地图名＋小型森林高台缩略图。中央两列队伍卡，左蓝队、右红队；各座位显示头像、名字、人/AI/靶子图标。卡片之间用小绳结表示相邻座位链接，3v3两段、4v4三段。

下方居中是人数分段按钮 `[2v2] [3v3] [4v4]`，再下方主按钮「开始对战」，左右角落为返回与设置。只有房主能调人数、地图和开战，加入者看到同步后的结果。

人数变大时补空位或AI，已有真人保留。人数变小时先删除超出的空位/AI；若超出座位有真人，先安排换位，不能默默把同伴踢出。换队/换位由服务端确认，冲突时保持原位置。

“人齐”定义为当前启用座位都有明确参与者，且已完成加载；不再额外增加一轮准备按钮。联机默认空位等待真人，房主点座位的机器人图标可补AI；本地AI模式直接补齐。人数切换仅发生在等待房，开战后固定。

训练也显示相同人数预设：2v2为本人＋1静止同伴，对侧2靶子；3v3为本人＋2静止同伴，对侧3靶子；4v4为本人＋3静止同伴，对侧4靶子。训练按钮明确使用伙伴/靶子图形，避免看起来像要等其他真人。训练预设是本稿建议，保证原“最多3名静止队友”的需求继续成立。

### 3.5 开战、暂停与结算

开局只显示居中3、2、1及短音，随后HUD进入。ESC打开居中设置面板；联网时阻止本地输入但不暂停其他玩家的比赛。返回、音量和退出各有清楚按钮，不常驻技术解释。

结算中心展示胜队角色小合影和胜负标题，下面再放K/D/伤害。全灭与计时判胜用简短图形＋必要标签表达。房主“再来一局”回原等待房，保留名字/选角/真人座位并可重新选择2/3/4人数；清空本局状态与复活队列。

## 4. 战斗HUD：红心是第一优先级

### 4.1 右上角生命区

右上显示自己的小头像和红心，红心槽数等于当前最大生命；失去的生命变灰心。现有最大生命为1/3/5点，应表现为1/3/5格；盾另放蓝色盾牌，不占红心。以3血剩1血为例：`♥ ♡ ♡`，实际使用像素图标，不用字符当最终素材。

在1600×900画面中，建议每颗心约40–48像素，安全边距32–48像素；720p仍要明显可辨。受击对应红心短闪后变灰，最低血时用头像描边/心跳提示，不把整个屏幕持续染红。

换枪使最大生命改变时，心槽数量和当前填充同步变化，短暂展示武器小图标，避免被误认为无故伤害。满血的灰槽与缺血的灰心含义分清：只画当前最大生命以内的槽，不额外常驻5个槽假装所有武器都是5血。

倒地时当前心全部灰，头像旁出现5秒复活环；复活后红心恢复到基础生命对应数量。护盾消失单独破碎反馈，不能让红心在未扣血时变灰。

### 4.2 其余HUD布局

| 位置 | 内容 |
|---|---|
| 顶部中央 | 时间＋双方存活头像，例如2/3、3/3；不得把人数误当成击杀比分 |
| 右上 | 本人头像、红心、护盾、倒地复活环 |
| 右下 | 当前武器图、E槽道具图、必要冷却遮罩 |
| 左上 | 收缩/延长/弹性效果图标与简短到期环 |
| 角色附近 | 本地固定脚标；队友简名；短时命中/倒地反馈 |
| 屏幕边缘 | 屏外队友头像/方向箭头，倒地者带复活环 |

移除顶部大黑条和常驻K/D文字。红心与敌弹、绳索、角色保持视觉优先级，地面装饰不争抢高亮。

## 5. 摄像机：真正保持角色在中心

跟随本地角色的固定主体锚点，每帧显示结束后对齐到画面中心；不跟随鼠标或枪口，不因队友远离而自动缩小。角色倒地时仍跟自己的身体，尸体被拖动时相机一起走；复活后连续接管同一角色。

当前鼠标前瞻、相机Lerp、地图边缘钳制和镜头随机震动都要调整：严格居中模式不允许这些偏移。枪械后坐、命中闪光和局部特效继续提供打击感。像素取整必须对角色/相机使用同一显示网格，不能相机单独取整把主体推离中心。

地图外侧绘制森林装饰缓冲区，宽度覆盖最宽支持屏幕的半个视口再加余量。逻辑战斗边界仍阻止角色离开；越靠边只会看到外侧树林，不通过钳制镜头把玩家赶到屏幕边缘。

验收：慢走、冲刺、拉拽、上下台阶、贴四边、倒地拖动时，主体锚点的屏幕位置稳定在(0.5,0.5)，容许不超过一个显示像素的量化误差。

## 6. 森林美术方向：按参考图取舍

参考图在 `art-proposals/2026-10-30/forest-v3-plan/user-forest-reference.png`。它的有效特点是：浅绿低噪声地面、深绿树墙、暖棕崖壁、浅色路面、统一树冠轮廓、能读懂上下层的台阶。图中密集高草和大量花不必全部移植，主战区要更干净。

### 6.1 画面构成

- 地面：2–3个低对比草地变体，配连贯的草土边缘与角块。只在局部使用碎石、草簇和花，主路保持连续。
- 树木：统一一套圆/锥形树冠，外围密、出生区适中、高台交火区稀疏。树干负责阻挡，树冠是可淡出的前景。
- 崖壁：统一高度、边缘厚度、内外角和落地阴影。低地和高台草色略区分，不能仅靠贴一个深色矩形假装高台。
- 道路：宽而清楚的浅土路通向台阶；枪械/道具放在读得出的空地上，不埋进高草。
- 障碍：少量石块和树桩成组布置，统一光向和底座，视觉轮廓与实际阻挡接近。
- 角色：保留八身份和高饱和轮廓；背景降低对比，枪再大也保留脸部辨识。

### 6.2 素材选择结论

**画面样板优先检查Tiny Swords；项目可公开协作的主素材候选优先检查Ninja Adventure。** 前者直接提供高台与台阶、风格整套；后者CC0，能减少源资源共享的限制。Tiny Swords原始资源禁止再分发，使用时将素材包与公共Git源码分开，保留取得说明；这不阻止使用它制作游戏样板。

候选完整比较在素材清单。Cozy Farm和Sprout Lands作柔和配色参考，免费版有非商用限制，不作为当前默认导入包。Kenney Tiny Town可作简洁轮廓/备用图标参考。最终只选择一套主环境语言，不把几套树、石、草拼成风格混合物。

进入实施后先取最小一组：草土＋崖壁/台阶＋树石＋现有蔬果，在实际游戏大小比较；确认树冠大小、轮廓、饱和度和像素颗粒统一后再铺全图。原参考图用于构图分析，不从截图抠出来源不明地块。

### 6.3 像素与图层规格

地块按所选包原生16或64网格组织，统一换算到逻辑栅格，禁止把16px树和64px树任意缩放混用。先以640×360世界画面预览，角色主体约28–40逻辑像素高作为可读目标，再锁定PPU与相机视口；不直接套旧图的尺寸。

场景分为：低地底面、高台顶面、崖壁立面、台阶、接触阴影、低矮装饰、人物/武器、树冠前景、战斗特效、独立UI。树干/箱石按脚底位置处理遮挡关系；树冠靠近人物时淡化，敌弹和关键提示应保持可见。

## 7. 第一张新地图：林间高台

### 7.1 空间拓扑

保留“大地图先适应绑定、再到中央交战”的目的。建议起始战斗区域约72×48世界单位，仅作灰盒测试候选；依据现有移动速度与3/4人绳链实际调整。视觉外围树林另算，不增加无收益跑图面积。

```text
                         北侧森林边界
          左侧上台阶 ===== 高台北路 ===== 右侧上台阶
              /              |              \
 左低地出生区 -- 左主台阶 -- 中央高台空地 -- 右主台阶 -- 右低地出生区
              \              |              /
          左侧下台阶 ===== 高台南路 ===== 右侧下台阶
                         南侧森林边界
```

中间二层是一块可绕行的宽高台，含中央交火区、上下侧路和少量掩体。左右低地各有准备空地、首枪、树墙和通向三处台阶的路线。主台阶宽，侧台阶提供绕路；不靠单一窄门把四人链堵住。

区域建议比例：左右低地各约20%，中央高台约45%，连接/过渡约15%。核心交火区大部分地面保持空净；密林集中外围，路口由明显的树组、台阶或石组当作地标。

### 7.2 各区区别化设计

| 区域 | 形象与用途 | 放置要点 |
|---|---|---|
| 蓝队低地 | 略冷草色、小木栅栏、开阔准备地 | 首枪距出生约3–5单位，避免枪械挤在同一点 |
| 红队低地 | 暖色路土、不同树组/木桩地标 | 几何和资源价值对等，不能靠颜色暗示攻击能力不同 |
| 主台阶 | 宽木/石台阶、连续两侧崖壁阴影 | 建议净宽4–6单位，先验证4人拖拽转向 |
| 高台中央 | 浅草/少量石地纹理，2–3组清楚掩体 | 留出对枪和绕绳路径，避免中间塞满装饰 |
| 高台北路 | 更开阔的远程侧路 | 放狙击等现有高价值武器候选，由数值同学定 |
| 高台南路 | 树桩/石块形成的近身绕行 | 提供匕首和状态物的争夺空间，不强制近战路线 |
| 外围树林 | 深色树墙、少量野花与草簇 | 负责背景和边界，不能误以为可走却被隐形墙挡住 |

2v2、3v3、4v4共用同一张主要地图，提供资源密度和部分路线宽度预设；首版尽量保留相同地形以便比较。资源左右镜像，差异化主要来自地标与路线选择，不来自出生队天然拿到不同道具。

### 7.3 高低层交互规则

采用俯视2D高台场地：每个XY区域首版只有一个可行走表面，不做桥下与桥上重叠空间。高台侧壁实际阻挡移动，角色和尸体只能经开放台阶上下，冲刺也不能穿过崖壁。

| 关系 | 首版规则 |
|---|---|
| 移动 | 低地↔台阶↔高台连通；高台其余边缘不可直接跨越，不加入跳崖 |
| 射击 | 保留XY弹道；崖壁挡弹，台阶开口允许有视线的射击。高度标签本身不产生免伤或高打低特权 |
| 近战 | 同一连通可见空间内按原范围判定；不能隔崖壁挥刀伤人 |
| 绳索 | 连续路径绕崖边/石树，并经过开放台阶连接两层；队友不被直线拉穿侧壁 |
| 拖尸 | 尸体仍有碰撞，可沿台阶拖上拖下；不在崖壁上自动传送 |
| 复活 | 在当前身体所属表面复活，不突然回出生层 |
| AI | 寻路知道台阶连接和队友绳链，不向“XY最近但中间隔崖”的点直走 |
| 爆炸 | 按现有半径及遮挡；崖壁阻隔，台阶开口按实际可见路径判断，不新增跨层全穿透 |

首版用真实边界碰撞＋台阶连接实现高台的空间意义，不要求换成3D刚体。地形显示、可行走区域、挡弹边、绳索阻挡和高度标签分开配置。中央高台内部是可行走地面，不能误导出成一个巨大的实心障碍矩形。

## 8. 新复活规则：存活队友决定能否回场

### 8.1 权威时序

1. 玩家HP归零，记录个人`reviveAt = deathTime + 5s`，进入倒地，保留身体和绳链。
2. 倒地期间不能移动输入、射击、用道具或捡装备；身体仍可被绳索拉动。
3. 该队只要还有活人，个人5秒计时继续；多个倒地者各自独立计时。
4. 同一物理步先结算所有伤害、炸弹及倒地，检查两队是否全灭，以及本局是否已经到时。全灭/到时优先结束，再判断复活；双方同一步全灭为平局。
5. 比赛仍进行且到达个人复活时间时，在身体当前位置复活。不要求活队友贴近，也不要求任何区域。
6. 结算、重开、退出清空待复活队列；计时结束按现有活人/血量判定，不在结算后补复活。

示例：A在10秒倒地，15秒能复活；若B在14.9秒成为本队最后倒地者，则本队在14.9秒已全灭，不等A回场。若B保持存活，A按时回来；A回场后B再倒地，也可获得自己的5秒机会。

自动复活可能提高打满180秒的比例。测试需记录全灭/计时占比与连续倒地次数，先调地图和牵引体验，不自行把胜负改成击杀积分。

### 8.2 复活位置、生命和保护

优先在被拖动后的身体当前位置起身。若该位置因场景边界/碰撞校正不合法，取同一可行走表面的最近安全位置，不跨崖、不回出生点，不用复活获得免费传送。

沿用基础3HP、清空武器和携带槽、盾归零；不自动重新赠枪。建议沿用当前2秒保护并在首次主动攻击时提前结束，防止保护期无代价输出；这项保护细节作为建议调试项单独验证。

移除地图复活底座、绿复活区、进区停留进度和相关AI目标。新版地图不再要求revivalZones非空；旧地图字段仅作兼容读取，不参与新规则。训练的对侧靶子维持训练专用自动重置，不让正式全灭规则终止训练。

## 9. 更强的绳索：能拖着跑，也能控制

### 9.1 当前拖不动的原因

现有绳索是弹簧＋阻尼＋最大力；同时移动控制每步会把角色速度拉回目标速度，未输入时目标是0。即使提高绳力，队友的控制器也会持续“刹车”。倒地质量当前还更大。因此本次需一起调整牵引、被动制动和尸体质量，而非仅把弹簧数字乘大。

### 9.2 目标手感

- 队友不按键时，一人向前走可把他明显带动；被拖者播放被牵引的迈步/滑步，而不是站姿瞬移。
- 双方同向跑更顺，反向输入仍有可理解的拔河；4v4中段队员受两段绳影响，不被强制指定某个人作领头。
- 松绳时各自操作正常，停步不能持续漂很远；拉紧后有短暂伸长和清楚回弹，不无限甩飞。
- 障碍和崖壁始终有效；牵引沿连续绕行路径施加，不能用传送或穿墙来显得“拉得动”。

### 9.3 首轮调参候选

下表为待实测候选，未改当前GameConfig；最终由程序与数值同学共同定。

| 参数 | 当前 | 建议首测 | 目的 |
|---|---:|---:|---|
| 基础绳长 | 5 | 先保留5 | 先比较力度，避免同时改长度干扰判断 |
| ropeSpring | 45 | 80–100，先试90 | 拉紧后更明显牵引 |
| ropeMaxForce | 100 | 180–220，先试200 | 能克服被动制动带走同伴 |
| ropeDamping | 6 | 10–14，先试12 | 控制增强弹簧后的抖动与反复回拉 |
| 倒地质量 | 1.6 | 先试1，与活人相同 | 保留拖拽反馈，降低尸体成为地锚的程度 |
| 被拉且无输入的速度制动 | 当前跟随acceleration=14 | 单独降低，不直接把速度归零 | 不让自身控制器抵消队友拖拽 |

基础行走速度先不改。牵引速度设合理上限，配碰撞扫掠；冲刺和弹性强化x3必须额外验证，不能把新的强基础绳再放大后直接放任穿透/爆速。对3人、4人链同时调阻尼与约束顺序，防止中间节点受力翻倍后振荡。

建议测试目标：空地一人主动跑、队友无输入，被拖者稳定达到约3世界单位/秒，主动者不长期停滞；松绳放键约0.3秒内明显停下。目标是调试门槛，不是当前已测数据。

## 13. 实现改动范围与协作

GameClient需要拆分标题/身份/模式/房间视图；LocalMatchRuntime与后端人数、座位及校验需支持3，所有列表/链条/结果不能硬编码4或8。模式控制训练伙伴、AI补位和真人加载条件，共用同一房间模型。

BattleWorld将区域复活改为权威个人计时队列，并把全灭判定放在到期复活之前；NetPlayer死亡、输入和保护状态相应调整。BotController删除找复活点的决策，增加跟随/牵引/台阶路线。RopePhysics与移动控制协同调参。MeadowCamera改为严格锚点跟随。

关卡编辑器新增地形表面、崖壁边和台阶连接，移除“必须有复活区”校验；同伴仍负责实际布局、资源和数值，程序/美术负责显示与导入。Tilemap负责绘制组织，数据负责权威导航/碰撞/绳索，避免某个客户端手画了高台而服务器仍是平地。

这是一批需要客户端与战斗服一起更新的规则变化；源码先本地验收，用户安排发布时再集中更新，保持现有NGO＋Node架构。
