# 派对射击 / Bound Shoot：产品级Demo提升策划

版本：v2.0评审稿。日期：2026-10-30（Asia/Shanghai）。配套：[全面检查报告](PROJECT_AUDIT_2026-10-30.md)、[执行任务表](PRODUCT_UPGRADE_BACKLOG_2026-10-30.csv)。

实施跟踪：同日已启动M0/M1首批，代码与验证详情见[首批实施说明](PRODUCT_UPGRADE_M0_M1.md)。下文保留原策划目标，不代表所有阶段均已实现；逐项状态以任务表为准。

本轮交付是检查与详细策划，不包含游戏实现。下文新增流程、表现、指标和日程均为建议目标，尚未落地。当前事实依据本地源码、已有Unity渲染与测试报告；网络参考仅使用开发者/发行商页面、官方文档和官方示例仓库。

## 1. 产品方向与成功标准

**把“被队友牵住、绕障碍配合射击”做成一眼可见、第一次能懂、反复玩仍有变化的蔬果派对对战。** 八个小人和夸张大枪负责记忆点，绳索和地形配合负责玩法记忆点。

这一阶段交付一个范围明确、可以连续演示的高完成度Demo：一张经过验证的草土主地图及2v2/4v4摆放预设、八个纯外观角色、现有四类武器和八种拾取物、完整训练/组队/战斗/结算循环。扩大内容库放在核心体验达标之后。

### 1.1 固定边界

- 保持消灭/计时竞技；默认2v2，最大4v4。计时比较存活人数、再比较存活成员血量，沿用现行规则。
- 仍是输入名字进入，不增加注册、密码、职业、成长树、付费系统或局外养成。
- 八外观可重复选择，碰撞/属性相同。2v2四人任选四种或重复，4v4也不强制八种各占一个。
- 踩不同武器立即自动换枪，不加确认键、背包或手动换枪列表；现行换枪不回血、不刷新冷却继续保留。
- 状态道具拾取即用；冲刺/炸弹单槽携带，E使用，新物覆盖旧物，死亡清空；问号盒解析为现有道具。
- 保留队内相邻座位的绳链、尸体牵制和现有区域复活。4v4是一条三段链，不改网状。
- 训练房增加的1–3名队友保持没有自主AI，但仍受碰撞与绳索物理影响；正式对战空位由AI补齐。
- 草地、土地、树木、土堆和石块主题继续，不退回赛博火柴人；保持大地图目的，但根据交战密度调整有效区域。
- 先在本地完成体验；不更换NGO＋Unity权威战斗服＋Node房间/会话架构，不因为产品打磨重写为Skynet或第三方联机框架。
- 游戏内只展示操作必要信息。开发说明、测试清单、网络架构放MD；不放满屏教程段落。
- 不做搜打撤、随机地牢、缩圈、强制占点、关卡闯关、最佳三局制或额外获胜条件；这些不作为本轮必需功能。
- 本轮不构建、不打包、不上传云端、不推送Git。后续发布仍需按用户安排执行。

### 1.2 “产品级Demo”验收含义

达标需要同时满足：普通玩家能顺利进入并读懂战斗；绳索形成可控的配合与失误；武器反馈清晰；多人连续对局无阻断；风格和交互统一；有目标硬件和真人实测记录。自动化测试只是其中一层。

建议目标如下，全部是后续测量目标，不是当前实测结果：

| 目标 | 建议门槛 | 测量方法 |
|---|---|---|
| 上手 | 5名新玩家中至少4人，在首次训练60秒内发现移动、瞄准、踩枪、E使用 | 观察录像；只给操作设备，不在旁口头指挥 |
| 核心理解 | 首局后至少4/5能说明“我为什么被拉住”“怎么帮队友复活” | 简短问答＋回放具体画面 |
| 进入战斗 | 名字确认至单人AI对局可开始≤15秒，不含主动等待 | 本机常规运行计时 |
| 节奏 | 2v2首次有效交火中位数10–20秒；每局有至少2次明显绳索协作/牵制事件 | 首轮20局回放打点；阈值可随实测修订 |
| 平衡 | 镜像换边后没有明显固定出生优势；首轮每侧至少20局，胜率>65%即触发复查 | 人类队伍对调测试；不声称小样本即可证明长期平衡 |
| 稳定 | 连续20局、两种人数、等待/重开/退出均无卡死和未处理异常 | 自动化＋手动流程日志 |
| 画面 | 720p、900p、1080p及16:10窗口，关键按钮和HUD无遮挡、文字不截断 | 实际渲染和鼠标点击检查 |
| 性能 | 明确测试机上1080p目标60fps，p95帧时≤16.7ms、p99≤33ms；记录CPU/GPU/内存 | 开发构建Profiler；构建阶段待用户后续安排 |
| 多人 | 4台机器、4人连续5局可结算重开；4v4至少8连接跨机压力通过 | 不能用同进程UDP代替 |
| 弱网 | RTT100ms、抖动±20ms、丢包1%时，能开局/交火/结算，状态最终一致 | 网络模拟＋双端录屏，记录纠正幅度和断连次数 |

## 2. 当前底子应该如何评价

已经完成的是“功能闭环Demo”，不是空工程：选角、训练、战斗、绳索、道具、AI、结算和关卡编辑器都存在。最新已存Unity报告为43项编辑器＋4项运行测试通过；本轮重新运行共享内容校验、4项后端测试和后端TypeScript检查，也全部通过。

最优先的五件事：

1. 修复等待房超时等阻断，补齐慢操作和退出重开的流程覆盖。
2. 把“按快照摆图”提升为连续的弹丸与绳索显示，确保攻击表现归属准确。
3. 让玩家看懂绳索张力、道具归属和危险提示，而不是单纯增加粒子数量。
4. 让主地图的资源、视野和碰撞轮廓真正服务绳索对战，给设计同学一个能快速测试的闭环。
5. 固定美术规格，先做一段完整高质量场景，再批量扩到八角色和全图。

全面证据、代码位置和问题编号见检查报告；本策划不把上一轮行走卡顿已修复的问题重复当作未修功能，但要求后续显示管线调整保留其回归检查。

## 4. 玩家完整体验策划

### 4.1 名字与选角

初次输入名字确认后，进入角色选择和主行动区；下次启动记住外观，名字记忆作为便利设置，不视为账号认证。主行动优先显示“开始对战”和“训练房”。

选角色时整张卡片可点击，只有一个明显选中描边/脚标；选中角色播放短待机和举枪预览。名字、身份轮廓和枪械不能被按钮遮盖。八角色一页展示，不增加属性面板。

开发期“本机创建/局域网加入”放在折叠区或次级面板。默认用户不能被要求理解127.0.0.1；云端版本未完成时不提供一个可点击但无法玩的入口。此阶段保留清晰的本地对战主路径，不虚构云端已可用。

### 4.2 等待房

展示两队、座位序号、头像、名字、人类/AI标记和简洁地图缩略图；座位顺序同时表示绳链连接顺序。默认2v2，房主可切4v4和选择可用地图，改变人数后先检查现有真人座位。

新增“入座/换队”属于建议的房间打磨：点击空位或AI位申请，服务端分配并更新所有人；冲突失败只给必要错误。等待房中可换外观，名字不占用持久账号。房主单人也可直接开始，空位自动AI；不强制所有人点准备来增加调试步骤。

进入连接阶段有可取消的进度状态和明确失败信息。手动房间等待没有隐藏60秒失效；专用服准备超时独立处理。

### 4.3 出生至交战

保留3秒开局倒计时。出生后3–5单位内有容易踩到的手枪/AK，宽路旁有单个大石块。两人先发生一次轻微拉扯，再进入汇合区；不通过禁止攻击、强制弹窗或站桩教程来分阶段。

局部引导只用地面方向、武器轮廓、短键位图标和一次性细小操作提示；已有WASD/鼠标/E不变。训练可显示必要键位，对战不常驻教程段落。

### 4.4 战斗与倒地

本地角色固定脚底标记；同队显示简名与状态，敌人只保留判读所需血/盾和队标。近距离重叠时姓名错位或隐藏次要名字，不能盖住子弹。

倒地显示躺下姿势、暗化装备和保留的绳链；队友能看到最近可用复活区方向。进入复活区显示进度环，离开按现行规则清零，受保护复活用短暂盾形边缘。不能把倒地“不可自主行动”误显示成已退出。

全队倒地仍按现规则结束，不添加死后自动重生或新的团队生命池。4v4尸体仍保留在原座位链中。

### 4.5 结算与再来

首先展示胜负、获胜依据（全灭/计时，计时时显示比较用的存活人数/生命），然后展示头像和K/D/伤害。强调团队而非只奖励击杀；救援次数需要新埋点，放到P2，不能用猜测生成“最佳队友”。

房主“再来一局”回到原房间，保留真人连接、角色和人数，重置全部场上状态；再点击开始。非房主看到“等待房主”状态和返回按钮。连续重开和退出不残留相机震动、音效、Buff、子弹或旧UI。

## 5. 核心手感与显示系统

### 5.1 输入和动画

保留现有行走修复：连续12fps六帧周期、停止缓冲、脚底注册与Host插值。补测30/60/120/144渲染fps，前后侧朝向、受击、倒地、复活、换枪交界；行走不能因等待网络包而跳回待机。

站立脚底锚点不等于所有动画强行底部对齐：倒地旋转、复活拉伸要各自定义参考点。循环首末帧轮廓、脸、叶片不能突然换样；不能用加快播放掩盖素材错误。

远端本地玩家目前等待权威位置再Lerp，不具备完整输入预测。先测RTT0/60/100/150ms的按下至首次可见反馈，再分两步处理：

1. 本地瞄准、枪械后坐、脚步/起步表现可以即时响应；服务端shotSeq确认后去重。血量、弹丸命中、拾取和复活仍权威确认。
2. 如移动延迟仍不能接受，单独原型验证“显示代理＋输入序号确认＋权威纠正”。绳索和碰撞状态复杂，不把完整回滚预测混入一次美术改版。若表现代理无法安全限制误差，维持权威位移并调整玩法/网络预算，不能直接客户端改真实Body。

### 5.2 四类武器的表现契约

| 武器 | 体验身份 | 必需表现 | 保留/需要同伴评估 |
|---|---|---|---|
| 手枪 | 易读的基础点射 | 短枪口火光、单发干脆声、小后坐、清楚命中点 | 现行3最大血/1伤/0.45s只是基线，不在本轮修改 |
| AK | 持续压制 | 连续但不闪屏的火光、短曳光、轻散布式视觉变化、控声部连发 | 视觉散布不能与实际命中方向不一致；当前代码没有真实散布，不偷偷加入 |
| 狙击 | 高威力高风险 | 更长枪身、明显开火脉冲、细长可追踪弹道、清楚来源方向 | range100对大图视野风险需实测；不默认加入激光瞄准、蓄力或改射程 |
| 匕首 | 贴身突破 | 朝向明确的短斩弧、近战击中声；不播放射枪火焰 | 独立近战事件和挂点；现行生命绑定与伤害由数值同学评估 |

每枪制作握把、枪口、后坐位移、层级和声音配置。角色脸常态至少保留主要轮廓；武器不能为放大而改变人物碰撞。人物贴墙射击要验证枪口可达性，弹丸不能从墙另一侧出生。

### 5.3 子弹连续显示

保留30Hz权威物理、15Hz世界快照为初始预算，不直接提高到60Hz。先为弹丸提供稳定ID与发射时间，客户端在帧间绘制连续轨迹，收到命中/到期事件后回收；权威修正限制外推时间。

开火、近战、命中、爆炸采用明确事件，静态拾取物走状态变化；减少用全量JSON反复重建已知显示状态。是否改为二进制增量在Profiler/网络抓取后决定，不把序列化重写列为首批必需项。

### 5.4 绳索是第一核心视觉

| 状态 | 视觉/声音 | 玩家应理解的内容 |
|---|---|---|
| 松弛 | 队色细绳、稳定连接脚底附近 | 仍有移动余量 |
| 接近拉紧 | 绳稍变亮、端点出现朝拉力方向的小提示 | 继续走会牵制队友 |
| 强拉 | 粗细变化受限、短促拉绳声，避免每帧重复 | 是绳在拉我，不是输入失灵 |
| 绕障碍 | 拐点绳结/小高光，不穿石；短暂强调最近受力拐角 | 应与队友绕哪一侧松开 |
| 收缩/延长 | 绳端图标与HUD小状态栏；按效果改变图形 | 哪队长度改变、何时恢复 |
| 弹性强化 | 纹理节奏或弹簧结，独立于队色 | 双方回拉更强 |

所有显示基于权威绳长、当前路径和效果截止时间。不要为“好看”重算全局最短路径导致换边；继续使用连续拓扑路径。Host和远端都在显示阶段用对应显示位置对齐端点，不改变物理解算。

4v4三段同时受力时，突出与本地玩家直接相关的1–2段，弱化远端队绳，不能把六条绳都画成高亮激光。长时间缠绕和冲刺首先保证稳定，再调回拉强度。

|---|---|---|
| 收缩 | 对方队绳端收紧符号、短促音 | 对方队状态小图标＋到期时间；同类重复按现行刷新截止时间 |
| 延长 | 我方绳端扩展符号 | 与收缩可同时存在，按基础长度乘积计算，结束不累计漂移 |
| 护盾 | 盾图标飞入角色、轻脉冲 | 一点盾清楚可见，与生命分开；挡伤后熄灭 |
| 冲刺 | 进入E槽；使用时短方向拖影 | 使用一次立即清空，位移受碰撞和绳索限制 |
| 炸弹 | 进入E槽；使用时落地弹跳 | 3秒警告圈/节奏提示，爆炸范围和遮挡符合实际伤害，不虚画超大致死圈 |
| 弹性强化 | 双方绳出现同类弹簧标记 | 两队皆显示到期；保留x3现行逻辑，不额外永久叠加 |
| 血包 | 短绿色治疗符号 | 实际增加1点，满血不能播放“加了血”的误导反馈，可显示已满的轻提示 |
| 问号盒 | 很短的揭晓动画，显示解析后的图标 | 解出状态立即生效，解出使用道具覆盖E槽；不暂停战斗或打开选择窗口 |

携带覆盖动画控制在约0.15–0.25秒，目标是说明变化，不阻止立即使用。状态到期提示走服务器时间，无需每帧网络倒计时。音效和图形承载含义，长文字只写在文档。

## 7. 地图与关卡协作

### 7.1 保留大图，重做有效密度

当前80×64空间比旧32×24约大6.7倍；不是要继续扩大。两队出生x±31，按moveSpeed5计算，理想无障碍同时向中央直走约6.2秒相遇，实际装备/绕路会更久。这个推算只是起点，不能代替交战录像。

保留草地和土路的开放感，把可交互内容组织为五区：左出生准备区→左绕行过渡区→中央多入口交火区→右过渡区→右准备区。上/下副路形成侧翼连接，不铺满孤立补给点。

```text
        上副路：远程武器 / 侧翼掩体
           ╲       │       ╱
 左准备区 ─ 左过渡 ─ 中央交火 ─ 右过渡 ─ 右准备区
           ╱       │       ╲
        下副路：近战切入 / 风险道具
```

该图表达拓扑，不是精确坐标。具体摆放、射线和数值仍由关卡同学在编辑器中完成。

### 7.2 2v2与4v4预设

共用自然主题和主要地标，提供两个清楚预设，不让同伴每次重建美术。

- 2v2：有效交战集中在中央和上下接近路线；外围保留视觉空间，减少需要穿越半图才有收益的散点。每段主路建议净宽至少3个角色直径，能并排或错身。
- 4v4：增加可绕行入口和同等收益补给，给四人三段链转弯空间；不要简单把2v2所有点位数量翻倍，造成满地道具和六绳混线。
- 第一验收地图左右同类资源镜像。收缩/延长等特殊道具可置于中区两侧等距点，不能左队天然拿一组、右队天然拿另一组后直接认定公平。
- 复活区保持现有可进入规则，不擅自更改队伍归属；用清楚底座和入口让玩家看得出在哪里复活。若同伴要改成队伍专属，必须视作单独规则变更评审。
- 每个高价值补给有至少两条进出路线，允许队伍绕障碍形成拉扯；不让出生点被跨屏长射线直接压制。
- 不加缩圈或硬强制汇合。若玩家持续回避中央，先调整资源吸引与路线密度，再判断是否需要新机制。

### 7.3 障碍与地面

石块/土堆有可读的落地底座，其可碰撞部分接近矩形实际边界；树干负责碰撞，树冠只装饰并在遮挡玩家时淡出。枪声、角色和绳索不能藏进树冠。地面装饰降低对比，草纹理避免明显大块重复。

首批继续使用轴对齐矩形障碍，不引入旋转多边形与可破坏物，避免破坏绳索求解。编辑器要能一键显示真实碰撞与绳索净距，作为设计工具，不在游戏常驻显示。

### 7.4 给同伴的编辑闭环

“选择地图→摆放→检查→保存→测试当前地图→回到编辑”形成一个闭环。本地房间可选新图和测试预设；实际开局显示相同地图ID/配置哈希，杜绝改了关卡却测另一张图。

新增验证：每出生点到首枪有通路；主要补给/复活区可达；队员转弯净距；关键对枪线长度；镜像资源统计；碰撞底座可视检查。现有只检查边界和点位重叠仍保留。

协作字段分开：设计同学负责地图/枪械数值/刷新；程序与美术负责显示挂点、特效、UI和导入规格。编辑器保存继续重读最新配置，保留已有冲突保护。拆分成独立地图/武器配置是后续改善，不作为本轮进度前置。

## 8. 统一美术与AI生产方法

### 8.1 视觉方向

主题是“干净的像素蔬果小队在草土庭院持大枪对战”。保留八角色脸、叶片、身材和颜色，不再反复改题材。角色高饱和、轮廓清楚；土地草地降饱和、减少高频噪点；危险、队标和可拾取物才用高对比。

当前PNG看起来像像素，但Point采样不等于统一逻辑像素。角色、枪、石头和背景各自任意缩放，仍会有像素颗粒不一致和旋转锯齿。下一步先做小场景规格实验，不盲目给现有大图套一个滤镜。

建议先以角色64×64逻辑画布、地面32×32逻辑tile、统一32逻辑PPU制作样板；实际角色内容占画布约40–48像素，留足动作空间。参考分辨率和正交尺寸一起验证后锁定：不要同时任意改PPU、缩放、取整和镜头尺寸。该规格是候选，不强行无损缩小现有AI图。

方案A：固定低分辨率世界渲染再Point放大，UI独立高分辨率；方案B：原分辨率世界渲染＋统一像素栅格。用相同角色和旋转枪对比行走、慢移和镜头跟随，选稳定且清楚的方案；不以“加了Pixel Perfect包”作为验收标准。

### 8.2 首批美术清单

| 类别 | 最小交付 | 质量要求 |
|---|---|---|
| 身份基准 | 8角色正面/侧面/背面基准与调色表 | 轮廓和脸一致、不同角色仍一眼可区分 |
| 动作 | 每角色前侧后行走6帧、待机、受击2、倒地4、复活4；复用侧面镜像 | 先验证一角色再扩八套；循环首尾、脚底、叶片不跳形 |
| 武器 | 四枪主体＋握把/枪口挂点＋每枪开火/近战反馈 | 枪明显大于普通道具，不能长期挡住脸和敌弹 |
| 道具 | 8地面图、7效果图标、携带槽与Buff小图标 | 24px/32px显示仍能辨认，不靠只有文字解释 |
| 地图 | 草/土过渡、2–3变体草块、2石、2土堆、箱/栅栏、树干/冠、复活底座 | 接缝不成方块拼盘，视觉底座与碰撞一致 |
| UI | 主背景、选中框、按钮三态、头像框、血/盾/道具槽、计时/结算框 | 主题自然但不做过度木纹装饰，交互优先 |
| 特效 | 四类攻击、环境/角色命中、爆炸、盾破、治疗、冲刺、绳索四状态 | 危险轮廓优先；避免发光雾团遮挡判断 |

### 8.3 AI迭代规则

1. 锁定身份图和单一风格模板，保留用户原图、生成版本、提示词和来源字段。
2. 先做“一个角色＋一枪＋一石＋一小片地面”的完整测试段，在游戏实际尺寸看，不以AI大海报判断可用性。
3. 动作逐方向、小批次生成，以身份图和相邻关键帧约束；先确认6帧循环再扩到其余方向，不一次生成整套后只检查张数。
4. 检查脸/叶形/四肢、透明边、画布、脚底/握把、颜色、首末帧；不合格帧重做。切片对齐只能解决注册问题，不能修复造型漂移。
5. 导入规格由程序保证，资源命名统一。每次替换必须经过站立/慢走/快走/转身/受击/倒地录屏对比；保留上一版可回退。
6. 八角色全量替换前先通过样板评审。旧赛博资源归档，不在普通Resources加载路径继续扩散。

现有原参考图作者信息未建立，manifest应如实保留来源；对外发行准备时补齐来源或更换为身份已确认的原创版本。本轮不以“AI生成过”宣称原图来源问题自动消失，也不为这个问题停止本地Demo研究。

## 9. UI、声音和可读性

### 9.1 战斗HUD布局

上方中心仅计时和双方存活头像；左下血/盾；右下武器和E槽；左上临时队伍Buff图标与短倒计时。击杀/倒地通知短时显示，不把K/D和所有状态堆成贯穿全屏的大黑条。K/D等详细统计留结算或按键临时面板。

生命和护盾有形状差异，队伍用颜色＋脚标形状双重区分；敌弹与我方弹不仅改红蓝，轮廓/亮度也能区分。必要提示不要求玩家记住色相。

不常驻调试帧率、IP、代码版本、服务状态或长操作说明。联机失败只显示玩家可采取行动的提示与重试/返回。

### 9.2 镜头与震动

相机先保证本地角色与直接相邻队友关系可读，再做有限瞄准前瞻。不能让震动改变瞄准世界坐标引入反馈循环；需要比较未震动逻辑相机与显示偏移。屏外队友提示有正确边界箭头、倒地/存活状态。

不强制跟随整支4人队伍缩到角色看不清。先保留个人跟随，通过方向提示解决队友屏外问题。爆炸才用明显震动；普通AK连发只轻微后坐，允许关闭所有镜头震动。

### 9.3 音频最小升级

四种攻击独立音色；角色命中、击倒、盾破、拾取/替换、绳拉紧、复活完成、炸弹预警/爆炸、胜负、按钮至少各有可辨短声音。加入1条低存在感环境/音乐循环，不做复杂配乐系统。

声部优先级：炸弹临爆/低血危险＞被击中/盾破＞本人攻击＞附近队友/敌人＞脚步与环境。限制同一时间重复枪声；音效/音乐独立音量和全静音。正式资源可继续AI合成或使用来源明确音效，记录清单；当前合成短音作为回退。

## 10. AI、训练和测试工具

正式AI目标是“陪人测试，不拖住人”，不追求竞争级智能。保留同规则武器/拾取/伤害，增加三项：绕障碍时感知两侧链张力；搭档倒地时朝复活点形成可走的拖拽路线；停滞超过阈值后重新规划，不以传送脱困。

对AI反应和瞄准误差提供设计参数，先检查现有0.25秒决策、0.35秒寻路与实际逐步瞄准，避免错误地假定它完全无延迟。AI不透过障碍开火、不读未公开玩家未来输入。

训练保留静止队友，增加可选显示工具：重置位置/道具、恢复当前状态、移动靶开关、绳索张力与碰撞覆盖层。调试工具放开发面板，普通训练只保留玩家需要的开关，不改变正式规则。

## 11. 联机与发布分层

### 11.1 继续当前架构

本地：Unity Host拥有权威物理和AI，其余客户端经UDP加入；训练不依赖Node。云端：名字入口/房间/票据/战绩由Node管理，Unity专用服决定战斗，客户端只提交输入。

本地与云端共享同一战斗规则、地图与资源定义。差异仅在会话建立和身份凭据，不能维护两套武器/道具行为。建议引入小型Session接口统一Start/Stop/Result通知，而不是大规模框架化。

### 11.2 版本契约

后续握手至少带protocolVersion、contentHash、mapId、teamSize和skin范围；版本不一致在进入比赛前拒绝并给清楚提示。游戏服启动日志记录相同字段，不能把版本“0.2.0健康接口正常”当作战斗兼容证明。

当前云端快捷房仍固定2v2、skin只到3，旧RPC与本地新版不同。恢复云端前需一次性更新会话、角色范围、人数、地图配置和Unity专用服，不是再开一个端口即可。

名字仅作访客显示名。重名时有会话内区分；恢复战斗凭据由会话票据决定，不以“再次输入同名”证明同一人。不增加账号流程，也不把匿名名字直接绑定不可替代的长期资产。

### 11.3 部署节奏

本地源码迭代→真人Editor/LAN验收→用户后续安排独立客户端构建→统一版本云端验收。平常改图、动画和手感继续本地测，不逐次上传。

到发布阶段再准备一个明确版本清单，列客户端、战斗服务、backend、配置哈希、备份/回退目录和启动检查。仍由用户使用现有SFTP方式集中上传；不把Bitvise作为玩家接入步骤。正式用户体验是启动客户端、输入名字、进入可用房间。

当前HTTP公网入口在对外开放会话测试前评估TLS和票据传输；不在本轮擅自申请域名、修改防火墙或服务器配置。该工作对应现有凭据链路，不是更换网络架构。

## 12. 工程质量与性能计划

保留既有资源、网络和关卡可用实现，采用小步拆分：显示与命中事件分离；HUD/Room/Result各自刷新；地图选择使用统一会话信息；热点再优化。

性能先建立基线：8人、6段绳、持续AK射击、集中拾取/爆炸、最大树冠遮挡，录制5分钟，另做30分钟连续重开。记录主线程、GC分配/回收、Draw Calls、音频声部、带宽与snapshot大小。当前JSON、LINQ和RaycastAll是候选热点，不预先断言它们已经导致掉帧。

优化顺序依实测：缓存玩家组件/字体→仅状态变化更新文字→非分配碰撞查询→减少重复排序/全量快照→静态场景组织和图集合批。池满优先保留危险提示，装饰粒子可让步。优化不允许改变命中/道具/绳索规则。

旧文件名CyberArt/CyberPlayerView可在稳定期逐步迁移，但这不是玩家体验首要事项，不用重命名制造大量无收益引用改动。

## 14. 验收矩阵与数据记录

门槛与统计范围：首轮5名新玩家判断可理解性，首轮20局判断节奏；平衡对比至少每侧20局后提出调整，统计仍是早期信号。功能验收、平衡结论、商业发行准备分别报告。
