# Unity 美术样板接入

日期：2026-10-29。已按用户要求将干净赛博朋克像素风接入 Unity 源码；没有构建 exe、服务端或压缩包，没有上传远端。

## 查看

1. 在 Unity 打开 `D:/workshop/developer_learn/Unity_Hub/Project/Bound_Shoot`。
2. 菜单 **Bound Shoot → Art → Open Art Preview 美术预览** 打开独立预览场景。它展示四名角色、队色、独立枪械、绳索、所有道具、地面、掩体和复活点；是静态美术样板，可在 Scene/Game 视图查看，不自动登录大厅。
3. 要操作角色，打开 `Assets/BoundShoot/Scenes/Boot.unity` 并 Play，输入名字，选择训练房。拾取枪械可切换，WASD 移动、鼠标瞄准/左键攻击、E 使用道具，按钮添加静止队友。选择 2v2 对战则走既有云端流程。

## 已接入内容

- 新生成三张透明 PNG：actors、items、environment，位于 `Assets/BoundShoot/Resources/Art`。角色和枪分离；四种武器、八种道具与四种环境部件共 20 个命名 Sprite 保存在 `Art/Slices`。
- Sprite 引用原始透明图，不将展示板的文字/背景导入；Point 采样、无 Mipmap、无压缩。导入菜单可以重建切片，现有 `.asset` GUID 保持。
- `CyberPlayerView` 显示极简角色、简单走路帧、独立瞄准枪械、倒地姿态、护盾与队伍标记。材质只替换青色亮条，红方显示洋红，保留枪身与头部原色。
- `ArenaView` 使用低对比地板与掩体图片，显示范围独立于原碰撞体；不修改设计同学的关卡 JSON、枪械数值或网络变量布局。
- 枪械与道具拾取物、放置炸弹使用图片；弹道改为细短队色条；绳索沿用真实求解路径并显示青色/洋红。
- UI 仅调整基础按钮与队色，保留必要中文操作标签。尚未完整还原 UI 提案中的装饰框和图标 HUD。

## 样板的边界

透明图片已可用于观察实机比例；仍是第一版样板。AI 走路帧没有达到精修逐帧动画质量，像素密度还需统一；角色暂用相同基础外观配队色。完整枪口、命中、爆炸动画和状态特效板尚未全部接入，目前沿用基础战斗反馈。场地暂未加入装饰植物、石头及远景城市层，避免妨碍关卡设计。

预览场景不会加入 Build Settings；Boot 仍是唯一启动场景。正式对战仍由既有 NGO 权威服务器运行，远端不需要为纯视觉素材变化修改配置。新训练房在本机启动本地主机，不占云端房间。

## 来源与复现

使用内置 image_gen，以用户认可的战斗概念图和对应素材板为参照，分别新生成透明角色/武器图、道具图、环境图。提示词强调独立图块、透明背景、极简角色与同一配色。原始生成结果保留在 `.codex/generated_images`，工程内 PNG 为其原样副本；切片由 `CyberArtImporter` 根据分区及 alpha 边界创建 Sprite 引用，不修改原图。

23 项 EditMode 检查通过（包括 20 个 Sprite、透明 alpha、Point 采样）；1 项 PlayMode 流程测试通过，覆盖本地训练启动、静止队友、换枪、冲刺、靶子恢复、重置、退出和再次进入。测试 XML 在本机 logs 中。批处理测试运行器写完通过结果后在关闭编辑器阶段停滞，已终止本次测试进程以释放工程；没有忽略失败测试。

最终截图见 art-proposals/2026-10-29/unity-preview.png，由 Unity 相机实际渲染，非 AI 生成的游戏截图。原始预览截图也在 Unity 工程 Logs/ArtPreview.png。测试曾暴露 NetPlayer MonoScript 导入缓存未解析，现由导入菜单强制重新导入并检查预制体引用后再继续。
