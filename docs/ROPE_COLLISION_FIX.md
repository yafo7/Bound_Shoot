# 绳索绕障碍换边修复（2026-10-29）

## 原因

此前 `RopeLink.Apply` 每个物理帧都调用无状态 `RopePath.Solve`，用可见图寻找全局最短路线。角色轻微经过对称线后，最短路线可能从障碍上侧变成下侧；端点直线可见时还会直接丢掉全部绕行点。这是重新选路线，并非一条连续运动的绳索，所以单帧所有线段都不穿墙，帧间仍能跳过整块障碍。先前测试只验证单帧可见性，没有覆盖连续运动。

另一个问题是找不到路线时返回端点直连，短暂重叠也可能被显示成穿墙。客户端插值后直接移动首尾端点，也未检查新的首尾线段。

## 改动

- 每条实际绳索拥有独立 `RopeRoute`，保存上一帧折线路径。每帧仅在两端附加实际移动轨迹，局部修补碰到扩张障碍边缘的线段。
- 去掉旧折点前，不仅检查新直线可见，还检查旧两段到新直线扫过的整个三角形是否碰到障碍。即使三角形三条边都畅通，内部包住障碍也不能直接收紧跨过去。
- 正常移动不重新选择全局最短路线；只有退绕回原侧、扫过区域畅通时才移除对应折点。不同队伍、不同绳索的路径状态不共享。
- 无解时不再返回穿墙直线。暂时重叠保留上一条有效路线，恢复后继续原绕行方向，避免下一帧借机换边。
- 弹簧和阻尼沿保留的折线路径作用，仍会将角色/尸体拉向原侧接触点；没有修改枪械、道具、绳长和弹性数值。
- 客户端用服务端折线作为基础，对插值后的端点做同样的安全变形，不再无条件将首尾线段拉入墙内。
- 训练房重置、靶子传送复活会显式清理相关绳索状态；普通移动、倒地和原地复活不清理。AI 导航仍可使用无状态最短路径，不与绳索绕行状态混用。

## 验证

新增回归测试：对称线两侧微移不换边；端点下移到直连可见时仍保持上绕；沿原侧退绕后正常解开；三条边可见但内部包住障碍时拒绝捷径；两条绳索分别保持上下绕行；显式重置；无解不穿墙；短暂重叠不丢失绕行；真实 Rigidbody2D 拉力仍朝原拐点。

最终结果：31 项 EditMode 检查通过（原有23项加8项绳索回归），1 项 PlayMode 训练房流程检查通过。测试报告：`logs/rope-editor-tests.xml` 与 `logs/rope-play-tests.xml`。原有地图编辑器、美术素材和训练房检查一起执行。

本次只修改源码、测试及文档，不构建、压缩、推送或修改云端。Unity 内本地训练使用新逻辑；已有 exe 和正在运行的云端战斗服务器仍需后续按用户部署流程更新，客户端图片更新无法替代服务端绳索计算更新。

绳索仍采用障碍折点路径加弹力的实现，没有改成刚体链。复测重点是卡角后的连续绕行、反向退绕和真实拉力，而不是观察单帧截图。
