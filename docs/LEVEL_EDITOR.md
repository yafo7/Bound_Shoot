# 给关卡设计同学：Unity关卡编辑器

2026-10-30 v3：载入「林间高台 / Forest_01」编辑新版森林。已取消放置复活区，旧字段不参与战斗；人数包含3v3。forest主题新增崖壁外观，保存保留plateau高台结构。高台外观与blocks崖壁须同步调整，操作限制见[实施说明](FOREST_V3_IMPLEMENTATION.md)。以下旧版复活区段落仅用于历史格式说明。

入口：Unity顶部 **Bound Shoot → Level Editor 关卡编辑器**。
当前只做编辑工具与数据接入，没有更改枪械数值、美术风格、云端服务，也没有生成新的exe或压缩包。

## 第一次使用

1. 打开Unity工程 `D:/workshop/developer_learn/Unity_Hub/Project/Bound_Shoot`。其他同学从Git克隆后打开 `unity-client`。
2. 打开 `Assets/BoundShoot/Levels/Arena_01.unity`，这是现有关卡的独立编辑场景；再打开关卡编辑器菜单。如果从Boot开始，也可以在编辑器选择关卡并点击“载入地图”。切换场景前按Unity提示保存原场景。
3. 在物件面板选地面、障碍、武器、道具或功能点，在 **Scene视图** 左键放置。Esc退出连续放置。
4. 选择物件后用W移动、R缩放，或在Inspector中输入XY位置和宽高；矩形右上角也有尺寸手柄。Ctrl+D复制、Delete删除、Ctrl+Z/Ctrl+Y撤销或重做。
5. 点击“检查关卡”，修正错误，再点击 **保存到游戏配置**。需要下次继续编辑时，再点“保存编辑场景”。

`保存编辑场景`保留Hierarchy、选择和编辑数据；`保存到游戏配置`才会改变实际游戏使用的地图。两者用途不同。Scene中打开Gizmos才能看到编辑预览。布局编辑不需要点击Play；实际联机从Boot场景启动。

## 可放置内容

| 类型 | 编辑内容 | 游戏行为 |
|---|---|---|
| 基础地面 | 关卡根节点的地面颜色、地图宽高 | 整张可走区域；边界自动生成墙 |
| 地面块 | 位置、宽高、颜色 | 只改变外观，没有碰撞，不是洞或可掉落地形 |
| 障碍柱 | 位置、宽高 | 阻挡角色与子弹，绳索和AI绕行按相同矩形数据计算 |
| 武器 | 狙击枪、手枪、AK、匕首 | 按所选种类生成，属性仍读取同伴维护的武器数值 |
| 道具 | 收缩、延长、护盾、冲刺装置、炸弹、弹性强化、血包、问号盒 | 使用已实现规则；问号盒随机池仍来自items权重 |
| 蓝/红出生点 | 队伍、队内位置1–4 | 每队各4个；当前2v2使用1和2，3和4预留 |
| 复活区 | 位置、宽高 | 显示区域和实际复活判定同步使用编辑的尺寸 |

地面和障碍使用轴对齐矩形，不支持旋转、多边形或任意3D模型碰撞。所有位置为XY平面，Z必须为0，物件Z缩放为1，关卡根节点保持原点、零旋转、缩放1。角色和道具当前仍用占位绘制，美术讨论继续暂停。

## 道具刷新

选中武器/道具后，在Inspector中设置：

- 刷新秒数大于0：被捡取后等待相应秒数重新出现。
- 刷新秒数为0：这局只出现一次。
- “刷新时随机替换内容”关闭：保持你指定的枪械或道具。
- 开启该选项：沿用原来的武器/道具随机刷新规则。

从旧地图载入的补给点保留原有随机刷新；新放置的物件默认固定种类、10秒刷新。状态道具立即生效，冲刺/炸弹仍放入一个携带槽并按E使用，不由关卡编辑器改变玩法规则。

## 新关卡与保存检查

填写新ID（例如Arena_02）和名称，点击“复制当前布局为新关卡”。新关卡默认未开放，完成后勾选“在游戏中开放”并保存，房间中的地图列表才能使用它。已有地图ID保持不变；需要另存时用复制功能。默认Arena_01必须保持开放。

保存检查包括边界、正尺寸、出生点座位唯一且完整、出生点间距、点位与障碍重叠、武器/道具分类有效、道具已启用、刷新时间非负等。每个关卡至少需要一个武器点和一个复活区。它不是自动通关或全图导航验证，复杂障碍组合仍需实战确认。

## 与枪械数值同学协作

- 保存地图时重新读取最新GameConfig，只更新当前地图，保留当时最新的武器、道具数值和其他地图。
- 如果同一张地图被另一个人/工具改过，保存会被阻止，需要先重新载入并协调修改，避免静默覆盖。
- 保存前仍建议先Git拉取，尽量避免两个人同时改同一张地图。这个保护覆盖本机编辑时的配置更新，不代替Git合并。
- 需要提交：编辑场景及其.meta，以及导出的GameConfig.json；编辑器脚本已在项目中。

## 实际游戏与服务器同步

运行时直接读取 `Assets/BoundShoot/Resources/GameConfig.json`。编辑器导出layoutVersion=1，含明确的pickups、floors和revivalZones；supplies/revivals仍镜像保留中心坐标供旧工具参考。未导出的旧地图继续使用原有补给和4×3复活区规则。

源码中的地图读取逻辑已接入新数据。现有exe/云端程序仍是上一轮版本，**仅保存编辑场景或只上传JSON不会更新旧程序**。需要测试新关卡时，由程序方统一构建客户端和Linux服务器，并同步同一份GameConfig到云端content目录，再重启Node服务。后续每次更新关卡也应同步三端配置，避免显示和判定不一致。本轮没有自动构建或操作云端。
