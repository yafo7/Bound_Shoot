## 3. 确定性问题与高优先级缺口

分级：P0为能阻断一场正常演示的问题；P1为明显破坏手感、理解或协作的缺口；P2为打磨、工作流与发布完善。证据“静态确认”只指代码分支成立，不冒充本轮实际运行复现。

### A01 / P0：本地等待房超过60秒可能永久停止推进

- 证据：`BattleWorld.cs:111–115`。`ManualStart=true`时不会自动开局，但等待超60秒仍执行`resultSent=true`。本地没有ServerRuntime，Abort不做事；之后FixedUpdate顶部持续返回。`BeginLocalRound`只切Phase和ManualStart，没有清除这个标记。
- 触发：创建本地房→等待65秒→开始；或结算后重开回等待房再等65秒。
- 影响：可能卡在倒计时，既有“马上开始”的测试没有覆盖。静态确认，动态复现待下一实施阶段执行。
- 改进：区分本地手动等待和专用服连接准备超时；明确会话与比赛状态，避免复用“已结算”标记表示无提示超时。
- 验收：2v2、4v4分别等待90秒开局、重开等待90秒开局；仍能开始、结算和退出。专用服真实连接超时仍应明确中止。

### A02 / P1：子弹显示被15Hz整包快照驱动

- 证据：`BattleWorld.cs:248–264`，子弹无稳定弹丸ID；客户端按数组序号复用对象，每次快照直接设位置，无逐帧推进。`GameConfig.json`为snapshotHz=15、弹速20/24/40。
- 影响：理论上每次更新跨约1.33/1.60/2.67世界单位；这是按弹速/快照频率的推算，不是实测屏幕跳跃。数组删除还会改变显示对象对应的弹丸。
- 改进：服务端保持射线扫掠命中；显示增加稳定ID、出生时间/初始状态、逐帧外推和权威销毁校正。先完成这一步，再评估是否有必要改序列化格式。
- 验收：30/60/120渲染帧率和模拟丢包下连续轨迹；穿墙/重复命中为0；不以视觉预测确认伤害。

### A03 / P1：枪口与后坐效果按“附近同队玩家”猜测归属

- 证据：`BattleWorld.cs:158–164`，ShotClientRpc只有位置、方向、team，再查0.8范围内第一个队员。
- 影响：队员贴近时可能让别人的枪后坐或使用错误音色；画面插值也可能令距离匹配失败。
- 改进：事件携带发射者稳定网络ID、武器ID和shotSeq；对应本人枪械挂点播放，并对本地即时表现去重。
- 验收：同队贴身同时开火的100次射击，表现归属无误；枪口被障碍挡住时不伪造穿墙成功反馈。

### A04 / P1：持枪长度、枪口火光与真实发射点没有统一挂点

- 证据：`CyberPlayerView.cs`的独立放大枪、`BattleWorld.Attack`的0.55单位逻辑枪口与ShotClientRpc的1.25单位火光分别硬编码。
- 影响：不同武器旋转时容易看到火光不在枪口，且美术遮墙与真实命中边界不一致。
- 改进：每枪配置视觉枪口/握把/后坐挂点；真实发射仍做从角色到枪口的遮挡验证。视觉放大不扩大玩家碰撞或让弹丸跨墙出生。

### A05 / P1：绳索增益没有可供玩家理解的完整状态显示

- 证据：BattleWorld的shortenUntil/extendUntil/elasticUntil为服务端私有截止时间；HUD只展示血、盾、武器、携带物和K/D，未展示长度/弹性效果与到期。
- 改进：同步最少量的队伍效果ID/权威截止时间；图标、形状和绳结反馈区分收缩/延长/弹性，不能仅换颜色。
- 验收：两种增益叠加再先后结束时，长度正确恢复；观察者能指出哪队受影响、是否结束。

### A06 / P1：炸弹及问号盒缺少明确结果和危险预告

- 证据：炸弹快照只摆图并着色；没有倒计时圈/范围轮廓；问号盒在ApplyItem内部解随机，随后拾取事件仍传原drop.item，所有普通拾取共用简化音效/图块分支。
- 改进：炸弹有3秒节奏加速和有效半径预警；问号盒反馈实际解析结果；携带槽替换有短促动画，状态道具即生效。
- 验收：不加长文字解释，试玩者能辨认炸弹即将爆炸、问号盒获得何物、E会消耗何物。

### A07 / P1：大地图两侧道具种类不对称

- 证据：Field_01实际配置：左侧item1/2/3/4，右侧item5/6/7/8，位置虽镜像，收益类型并非对等。`FieldMap.cs:27`也生成同样布局。
- 影响：不能从障碍几何镜像推出平衡；尚无真人胜率数据证明偏向哪边。
- 改进：第一张验收图使用镜像同类道具；差异资源移到可争夺的中区。设计同学保留最终点位与数值决定权。

### A08 / P1：编辑器新增关卡不能从本地入口自由选择测试

- 证据：`LocalMatchRuntime.cs:30`固定FieldMap.Id；GameClient的本地房间没有地图选择。编辑器可创建任意地图，但默认流程仅测试Field_01。
- 改进：本地房主可选available地图并生成一致的地图会话数据；编辑器有“测试当前地图”入口；不能只编辑成功、开局却进另一张图。

### A09 / P1：新本地版与云端旧入口的角色/人数契约不同

- 证据：本地skin0–7及2/4队伍大小；backend `service.ts:66`只允许skin0–3，`rooms.ts:93`快捷房固定2v2；旧云端RoomScreen仍只有4外观按钮；新版云端按钮已禁用。
- 影响：不是当前本地无法游玩的原因，却是未来恢复云端的明确阻断。仅复制新GameConfig不能统一这些代码和新RPC。
- 改进：维持现有架构；本地体验验收后统一schema/protocol/content版本，再由用户集中上传三端一致版本。
- 本轮没有连接VM验证线上版本，也没有开启禁用入口。

### A10 / P1：现有测试缺少真实多人、慢等待及完整体验验收

- 证据：LocalMatchTests同进程UDP，网络流程测试有主动Hurt推进结果；未覆盖90秒等待、断网恢复/满员并发等完整矩阵；没有Profiler或4/8真人体验记录。
- 改进：分层验收：代码自动化→Editor真人→跨电脑LAN→用户批准后独立客户端/云端。任何一层不得替代后一层。

### A11 / P1：给关卡同学的规则文档已过期

- 证据：`docs/DESIGNER_HANDOFF.md:14`仍写首次拾枪满血且锁定；当前NetPlayer.Equip允许踩枪替换、不回血并保留更长冷却。
- 改进：下一实施阶段先更新唯一有效协作规则；旧文档标记历史。当前策划明确现行规则，不在本轮覆盖原文档。

## 5. 下一阶段第一批复现清单

1. 2v2等待90秒再开、4v4重开后等待90秒；记录Phase、resultSent、Clock。
2. 三把枪分别60fps录屏，逐帧量测弹丸位置变化；同时比较host/client。
3. 同队贴身同时开火，核对枪口、后坐、声音归属。
4. 两队绕同一障碍相反方向、拉尸体经过拐角、冲刺后回拉，持续10分钟；记录穿墙/换边/恢复过程。
5. 收缩＋延长＋弹性先后覆盖/结束；问号盒出冲刺后覆盖炸弹；确认槽、时长、受影响队伍。
6. 等待房满员、两客户端同时加入、客户端退出、房主退出、网络瞬断、重新开局；都能回到可操作状态。
7. 编辑器复制地图保存后从本地入口选择，实际出生点和拾取物与导出一致。
8. 4真人首次试玩，不讲解玩法，记录能否发现绳索、踩枪、E道具和救援；避免仅用开发者熟练操作判断易懂。
